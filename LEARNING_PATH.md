# Learning Path

This is the canonical role-based learning sequence for the AEM Technical Lead Playbook. Use it with the published [documentation site](https://srma4tech.github.io/aem-technical-lead-playbook/) and check the [Roadmap](ROADMAP.md) and [Release Dashboard](docs/release-dashboard.md) for current content status.

## Audience tracks

| Track                     | Entry point                                                                                             | Intended outcome                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| AEM Developer             | [Understanding AEM Internals](docs/20-understanding-aem-internals/README.md)                            | Explain request flow, resource/script resolution, rendering, and repository interactions             |
| Senior AEM Engineer       | [Engineering Principles](docs/00-engineering-principles/README.md)                                      | Investigate production behavior with evidence and account for performance, security, and reliability |
| Technical Lead            | [Technical Lead Principles](docs/00-engineering-principles/02-technical-lead-principles.md)             | Guide design and delivery decisions, reviews, and team learning                                      |
| Future Solution Architect | [Engineering Principles](docs/00-engineering-principles/README.md), followed by the technical-lead path | Evaluate system-level options, constraints, cross-cutting risks, and architecture governance         |

These tracks are guidance, not certifications. Follow the path that matches your current role, and revisit foundations when needed.

## Progression

1. **Engineering foundations** — engineering mindset, clean code, production ownership, decision-making, performance, security, debugging, and mentorship.
2. **AEM internals** — request lifecycle, Dispatcher and Apache, Sling resolution, HTL rendering, JCR/Oak, response generation, and common request problems.
3. **Delivery and platform quality** — AEM Core, Dispatcher, performance, security, and AEM as a Cloud Service. Check the roadmap for publication status.
4. **Enterprise engineering** — Java, design patterns, system design, integrations, and production support as these sections are published.
5. **Leadership and architecture** — technical leadership, architecture decisions, reviewed cases, interviews, and references as these sections are published.

## Practice checkpoints

For each stage, aim to demonstrate that you can:

- explain the system behavior in your own words;
- trace requests, dependencies, and failure paths;
- identify evidence needed before choosing a fix;
- compare alternatives and articulate trade-offs;
- define validation, observability, and recovery checks;
- communicate the decision clearly to the intended audience.
